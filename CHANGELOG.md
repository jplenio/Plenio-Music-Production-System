## 2.0.0 - unreleased

### Added

- **A model plan** (`plenio/core/modelplan.py`): for every model a template needs, Plenio works out which file suits the graphics card - the best that runs on it, keeping an installed file that is nearly as good - and says why in a sentence. `[models] prefer` (`balanced`, `quality`, `speed`, `small`) and `[models.pins]` in `config.toml` override it. The memory figures are estimates until measured; the plan is not yet used by the templates.
- **Model Choice** (`Plenio/Model`): one node per model that hands its file's name to the loader beside it. `auto` takes the file that suits the computer that runs the workflow, when it runs - a pin in `config.toml` comes first; any other entry is your own choice, a finetune too. Its summary says which file and why; a missing file stops the run with its name, folder and address. The model blocks of the templates - *Plenio · YuE2 Model*, *Plenio · MiniMax Model*, *Plenio · Cover Art* - have one such field per model, set to `auto`, so a template made on one computer takes the right files on another. Their loaders no longer ask ComfyUI's missing-model dialog for the default file, which was the wrong file on a computer whose card suits another. A workflow saved with 1.x keeps its blocks and the files they name. The release record notes the file each Model Choice took (`models`), and the player's song page names it.
- **A download manager for model files** (`plenio/core/assets/downloads.py`): queue, two at a time, pause, resume from a partial file, size and SHA-256 checked before a file is put in place, and every refusal of the host in words - terms to accept, a missing token, a moved file, a busy host, a full disk. A Hugging Face token is sent to huggingface.co only, never along a redirect. A different file that already has the catalogued name is left as it is and named, never deleted or replaced. Plenio Setup's routes (`/plenio/setup/*`, this computer only) list the plan, start downloads by catalogue id and keep the token; the page for them comes with Plenio Setup.

### Security

- **Routes for this computer only also check the address a request was sent to.** A web page whose name was pointed at 127.0.0.1 (DNS rebinding) reached them from the browser of this computer; its `Host` header still names the page, and is now refused. `localhost`, loopback addresses and the computer's own address and name still work.
- **Where a song's time went**: the release record says how many seconds each group of the template took, how much of that ComfyUI spent loading models, and the peak memory on the graphics card (`timings`, `plenio.timings/1`). A record without it reads as before.

### Changed

- **Every model file is pinned and has its hash.** The model catalogue now lists components and their variants (`resources/models.toml`, schema 2): each file's link points at a fixed commit and carries its size and SHA-256, read from the host's headers by `tools/catalogue_check.py` and checked weekly. Twelve links pointed at a branch before; three named repositories Hugging Face has renamed since.
- **The Comfy Registry package starts no other program.** Plenio now comes in two forms. The package of the ComfyUI Manager and `comfy node install` starts nothing but ComfyUI's own Python with Plenio's own modules - the lyrics ASR worker, the Plenio Player opened from ComfyUI, llama-cpp-python for a GGUF file. Three conveniences that start another program moved into the *Studio add-on* (`plenio/addons`), which a `git clone` and the release zip carry: the player starting ComfyUI, an installed `llama-server` running a GGUF file, and *Open the folder* opening the file manager. Without the add-on each says what to do instead: the player finds the ComfyUI you start and says so, GGUF models run in LM Studio, Ollama or a `llama-server` you started (or with llama-cpp-python, else ComfyUI's own Gemma writes), and *Open the folder* shows the path with a *Copy* button. **0 · System Check** says which form is installed; `PLENIO_ADDONS=0` switches the add-on off. A check on the packed zip (`tools/package_gate.py`, in the CI) fails the build if a launch site comes back. [Two ways to install](docs/user/getting-started.md#two-ways-to-install), [SECURITY.md](SECURITY.md#programs-plenio-starts).
- ***Open the folder* opens the folder**, no longer with the file selected in it: selecting needed a command line built as one string. Explorer now gets the folder as one argument.
- **Workers run on ComfyUI's own Python only**: the worker protocol no longer takes another interpreter.
- **Every route has an access class** (`local`, `compute`, `data`, `api`), declared in the route table and checked for every route; what the routes answer is unchanged.

### Fixed

- **The FLUX.2 VAE no longer counts as incomplete**: the catalogue had its size wrong by 2 kB, so the System Check and the API's `/models` said *size differs* for a correct file and the cover-art templates were *not ready*.
- **The Plenio Player opens from ComfyUI without a pause.** Looking for a running player waited two seconds for every port nobody listened on - ten seconds on Windows before a player was started. Measured: 10.2 s before, 1.3 s after.

## 1.6.0 - 2026-11-09

**The Song API for DAWs (API 1.4): stems with every take, the bars of a take, the models a template needs.** Programs that put Plenio's songs into a DAW - the [Plenio VST3](https://github.com/jplenio/Plenio-VST3) plug-in, the SoundCraft add-in - get what they need from the API itself instead of routes of their own: a job's take comes with its stems on request, every bar of a take can be asked for to set a DAW's tempo map, and the API says which model files a template still lacks. Everything only adds to API v1; a program written for 1.3 works unchanged.

### Added

- **Stems with the take** (`"stems": true` in a job request): the template's Master separates a take into stems when its Stems switch is on; this option turns it on and has the Stem Mixer save every stem - Export Release writes `vocals`, `drums`, `bass`, `other` and `rest` (what the stems miss) beside the song into `<name>-stems/`, listed in the result's files with `role: stem` and the stem's name. The song sounds the same; the separation (BS-RoFormer, on the graphics card) takes about half a minute more. The Stem Mixer's value has a new field for it, `save_all` (every strip saved, whatever the separation names its stems). A file's name may now hold that one folder when it is downloaded.
- **The bars of a take** (`GET /jobs/{id}/bars`): where every measure of the score lies in the take's audio, measured from the onsets, the score's harmony and the sung words - a YuE2 take keeps no steady tempo, and a DAW sets one tempo per measure from this, so that its metronome and further tracks keep to the take while the audio stays as it is. Made and measured in the SoundCraft add-in (the start of a song reckoned back from the first stretch that is sure), now `plenio/core/bars.py`; measured once and kept beside the record (`<name>.bars.json`).
- **The models a template needs** (`GET /models`): every model file of the API's templates - installed, missing or of another size, its size, folder and licence - and per template whether it can run.
- **`features` in `GET /`** (`stems`, `bars`, `models`) and the new paths, so that a program sees what the running Plenio offers.

## 1.5.1 - 2026-11-07

**Notes that fit their lyrics, tracks you can lock, lyrics placed by hand that stay, and a better writer by default.** The Score tab marks every lyrics line whose notes do not match its syllables and fits the notes to the words - the whole song or the selected lines, in one undo step -, and the Vocal or the Instrument melody can be locked while the other one is edited. Lines placed by hand in the lyrics lane keep their place, a double-click on free room starts a new one, and a click on a chord symbol sounds it. Gemma 4 12B, chosen for the graphics card, is the default writer, and the YuE2 model block is open for a finetune. Your own lyrics are sung exactly as written, long descriptive section tags included; Export Release hears the lyrics on the vocal stem; and a cover's bars keep their place in the recording while their notes change.

### Added

- **Notes that fit the lyrics**: the Score tab marks every line whose notes do not match its syllables, and *fit notes to lyrics* repairs the whole song, *fit selection* the selected lines, in one undo step. The text stays: the song's own melody is taken where it stands with the right number of notes, new notes follow the song's chords, key, rhythm and intervals and never clash with their chord or the instrument line, the notes that carry least go first, and spare phrases can move to the Ins. Repeated sections stay one melody. On 120 songs: 1778 of 3470 lines off before, 26 after (those without room, said so); none of the 1563 new notes clashes with its chord, 99 % stay in the key.
- **Lock a track**: the Vocal or the Instrument melody stays as it is while the other one is edited - pale in the roll and the notation, not selectable, safe from every edit. Bars inserted, deleted, copied or moved, sections arranged and key, tempo and meter changes still reach it, so the voices stay together.
- **New lyrics lines where the lane is free**: a double-click on free room in the Score tab's lyrics lane starts a new line there, from the click to the end of its phrase and never past the next line. Before, a line could only be added by copying one.
- **Hear a chord**: a click on a chord symbol in the roll selects it and sounds it once, in the chords' sound - root, quality and slash bass, with *hear* on. A drag does not sound it again, and a symbol without pitches stays silent and says so instead of playing a guessed triad.
- **YuE2 finetunes**: the guide says which files load, where they go and how the choice differs from a LoRA; **0 · System Check** says for every YuE2 file in `models/checkpoints` whether it loads and, if not, why (m-a-p's Transformers layout, a missing part). Tested with Plenio's own checkpoints; how a finetune sounds is not measured.

### Changed

- **The lyrics are heard on the vocal stem by default**: Export Release separates the take's vocals first (the model of Stems and Sung Pitch, about 25 seconds for three to four minutes), for more exact subtitles and player lines. *The song* stays as the quicker choice, and is the fallback without the separation model.
- **The default writer is Gemma 4 12B**, a clearly better writer of lyrics, titles and styles than Gemma 4 E4B. *Gemma 4 12B (auto)*, first in *Writer model*, takes a Gemma 4 12B GGUF already on the computer - in `models/LLM`, LM Studio's models or the Hugging Face cache, or of a running app -, else downloads the file for the graphics card once into `models/LLM`: Q6_K (9.8 GB) from 16 GB of VRAM, the QAT Q4 (6.7 GB) below, pinned by revision, size and SHA-256. A GGUF needs llama.cpp: without it nothing is downloaded, ComfyUI's own Gemma text model writes if one is installed and the node says so, else the run stops and says what to do. **0 · System Check** says what the writer takes on the computer, and its rule table has the writer's row per card. A workflow saved before keeps the writer it was saved with; Gemma 4 E4B stays in the list as the lighter writer that needs no llama.cpp, and no template asks to download it any more.
- **The YuE2 model block is open in the templates**, with its *checkpoint* in sight: the original or a finetune is chosen there, and the music model, its text side, the audio decoder and the Engine Profile all follow from that one file. Saved workflows keep their block as they were.
- **Lyrics lines never overlap and never push one another**: a line made longer stops at the next line, one dragged stops at the nearest line in its way (the status line says so) or, dragged far enough past it, lands in the free room behind it. A paste into a line is refused with the reason.
- **One edit in the lane keeps every other line where it is**: every sung line gets the span it has now, also the lines of other blocks, and a changed line keeps its span. Before, resizing a line or changing its words could move the lines around it, up to the following blocks, away from their notes. A line placed by hand shares its syllables over its phrases as the automatic layout does, so placing it changes no syllable; **auto-place lyrics** in the roll's tools lays the lyrics out on the notes again.

### Fixed

- **A bar keeps its place in the recording while its notes change**: moving notes between Vocal and Ins, *melody → Ins* and *silence* changed what a bar holds, and matching bars by content then sent the bar and the ones after it to another passage: the waveform, the source's playback and the sung pitch showed the wrong part of the recording, though the recording itself never changed. The editor now keeps which source bar every bar is - through edits, moves, copies, deletions, inserted bars (which have no source), undo and redo, Apply and the project file - and Transcribe Lyrics reads the same. Scores without it (older workflows, edits outside the editor) find their bars as one path through the recording, so an edited bar stays where it is, and the editor says how many bars are placed by assumption.
- **Your own lyrics are sung exactly as written**: a section tag stays as you typed it - also a long one that describes the section, such as `[Verse - Female Choir, Call and Response delivery]` (a tag of more than 40 characters was taken for a sung line, and a `[Verse]` was put before it) - and no line, blank line, direction or repeat mark is changed or left out any more. Only a `[Verse]` before lines without a tag is added, and markdown stars around a tag are taken off. A section named with a description counts as that section when the plan's song form, the words' places and the score editor compare sections, so YuE2's plan keeps its own section names.
- **The sung pitch stays where it is while notes are edited**: its octave is taken from the score as it opens; only a transposition or a track moved by octaves takes it along.
- **Dragging a chord symbol scrolled the roll upward**, a row with every move of the pointer: the chord lane lies inside the edge where a drag on the rows scrolls along. Dragging notes and frames to the edge still scrolls.
- **Set and remove stayed disabled for a selected chord symbol**: the toolbar's chord field now shows it, *set* renames it and *remove* removes it - several selected at once too -, with the same operations as the lane. The controls follow the score after the edit and stay disabled while it is busy or its text is invalid.
- **Shorter split a note tied over a bar line** into a short fragment and a second attack in the next bar: *shorter*, *longer* and `[` / `]` now change the whole note from its start, in both voices. It stays tied while it still crosses the bar line, loses the tie when it ends before it, and a rest takes the time it gives up.
- **Undo and the keys after a toolbar button**: a button disabled while the backend worked took the keyboard focus with it, so the next Ctrl+Z or `[` went to the graph behind the dialog.
- **A cut-off LLM answer says why**: the message tells the answer's limit from a full context, says how much was thinking where the app counts it, and names a model that thinks although thinking is off - its chat template ignores the switch -, with what helps in each case. A thought cut off before its closing tag counts as thought, not as an answer.
- **A wrong checkpoint in the YuE2 block** gets a message that names what loads: a YuE2 file in ComfyUI's format, not a GGUF or the Transformers layout.
