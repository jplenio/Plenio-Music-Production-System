# Plenio Music Production System - notes for a coding agent

A ComfyUI custom-node pack: song writing with local LLMs, YuE2 and MiniMax Music 3, an editable Song Sheet, covers, stems, mastering, release export, a Song API, and the Plenio Player (a program of its own). Published version: 1.6.0. **2.0.0 is prepared** (`release.py prepare`, not tagged), by [docs/design/v2-implementation-plan.md](docs/design/v2-implementation-plan.md).

## Rules that always hold

1. **Languages.** Answer the owner in German. Code, comments, UI strings, docs and commit messages are English (ADR-0008).
2. **Git.** Commit locally, one task or a coherent part per commit. **Never push, never tag.** Never commit `.codewhale/`, `.claude/` or `dist/`. End commit messages with the `Co-Authored-By` line of the session.
3. **No pre-release versions.** Everything goes into 2.0.0 on `main`; the owner tests it from the repository before publishing (decision 2026-11-11). `pyproject.toml` stays at 1.6.0 until the release is prepared; the CHANGELOG collects changes under *2.0.0 - unreleased*.
4. **Private material.** The owner's release records and songs (ComfyUI's output folder) are read-only study input: report aggregates only; never copy lyrics, titles or sung lines into code, tests, docs, commits or the CHANGELOG. Invent examples.
5. **Downloads and installs** (Python or npm packages, model files, browsers) need the owner's explicit permission, each time.
6. **Graphics cards.** GPU jobs on GPU 1 only (`CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1`), one at a time; never load GPU 0. Browser tests that draw WebGL use Playwright's own Chromium, never a browser channel.
7. **Public texts** (CHANGELOG, README, docs, release notes) say what changed and why it is better - never who asked.
8. **Claims.** A number is measured or labelled an estimate. Say "not rendered", "not heard", "not measured" plainly.
9. **Compatibility.** A workflow saved with 1.x opens and runs; `/plenio/api/v1` answers as in 1.6.0 for a caller on this computer; the player reads its existing state. Breaking one of these needs the owner's decision first.
10. **Outward-facing actions** (push, tag, post, issue, upload) are the owner's.

| `plenio/comfy/` | thin ComfyUI adapters; `host.py` is the only module that touches ComfyUI internals; `nodes/`, `routes.py`, `song_api.py` |

| `plenio/third_party/` | vendored inference code; not linted, not type-checked |
| `frontend/` | Vue + TypeScript sources; builds are committed (`web/js`, `plenio/player/static`, `plenio/player/guest_static`) |
| `resources/` | `models.toml`, `assets.toml`, schemas, templates' data; `example_workflows/`, `subgraphs/` are generated by `tools/build_graphs.py` - never edit their JSON by hand |
| `tools/` | build and check tools (`package_gate.py`, `workflow_validation.py`, `browser_check.mjs`, `dev_server.py`) |
| `docs/design/` | designs; `v2-product-design.md` (PD), `v2-marketing-and-publishing.md` (MP), the plan; `docs/adr/` decisions; `docs/dev/` how to work; `docs/user/` the guide |

Inside `plenio`, imports are relative (ComfyUI imports the folder under a path-derived name). Errors carry a message and a hint; every node input and output has a tooltip.

## Traps on this machine (Windows)

- **Git Bash heredocs mangle backslashes and quotes.** Write edit scripts with the Write tool and run them; use the Edit tool for exact replacements.
- **Line endings.** Git stores LF; some working files are CRLF. Normalise CRLF to LF before exact-text replacement, and write with `write_bytes` (Python's `write_text` writes CRLF on Windows). **Frontend sources must be LF before a build** - Vue's scoped-style ids hash the file as read, and the CI compares the committed builds (`git ls-files --eol frontend | grep w/crlf` must be empty).
- **Host tests copy the package when a server fixture starts.** Do not edit files under `plenio/` while a host run is in progress - a half-edited tree fails unrelated tests.
- **Host tests run the package without the add-on** (as the Registry ships it); `tests/host/test_registry_package.py` reads the tracked files, so `git add` new files before running it.
- A stale dev server on a port still answers; check `<base>/server.log` and stop the old process.
- `comfy` (comfy-cli) needs `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`, and packs only tracked files.
- Machine paths (ComfyUI, models, the reference export) are in the session's memory notes, not in the repository: no local path, private address or personal text may be in a shipped file.

## The package boundary (do not regress)

The Comfy Registry package starts nothing but `sys.executable` with Plenio's own modules, in three files (`plenio/core/workers/protocol.py`, `plenio/player/launch.py`, `plenio/core/llm/runtime.py`), each with the command written as a list in the same function. `tools/package_gate.py` fails the build on anything else: another launch site, `shell=`, `os.system`/`os.startfile`/`os.exec*`, `eval`/`exec`, `pip`, `pickle`, a script or binary file. A new function that starts a program goes into `plenio/addons/`, behind `features.has`, with its degraded sentence and a test for both forms ([ADR-0012](docs/adr/0012-two-artefacts.md)). Every HTTP route declares an access class (`local`, `compute`, `data`, `api`) in its table (`plenio/core/access.py`).
