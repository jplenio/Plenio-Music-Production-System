# Plenio 2.0.2

**No place on this computer reaches the network, a list field of a brief keeps what you choose, and a playlist to share is made on a phone too.**

> **New to Plenio?** Plenio is a free, open-source song production suite for ComfyUI that runs on your own PC: type an idea and get a finished, mastered song with cover art, timed lyrics and sheet music - sung by YuE2 or MiniMax Music 3. See and change every word, note and chord before it is sung, and play it to a room from the Plenio Player. [Listen first](https://jplenio.github.io/Plenio-Music-Production-System/) · [README](https://github.com/jplenio/Plenio-Music-Production-System#readme) · [Guide](https://jplenio.github.io/Plenio-Music-Production-System/guide/)

## Install

- **ComfyUI Manager**: search for *Plenio Music Production System* - or `comfy node install comfyui-plenio-music`.
- **The full download**: `git clone https://github.com/jplenio/Plenio-Music-Production-System` into `ComfyUI/custom_nodes`, or the zip below. It also carries the Studio add-on: the player starts ComfyUI, a `llama-server` runs a GGUF writer, *Open the folder* opens the file manager.

Restart ComfyUI: **Plenio Setup** opens and plans the model files for your graphics card.

## Every change

<details><summary><b>Security</b> (1)</summary>

- **Nothing that answers the network names a place on this computer.** ComfyUI has no login: with `--listen` everyone in the network reaches its routes and its history. Export Release named its release record by its absolute path in its output, which ComfyUI keeps in `/history` - it now names it by its place inside the output folder (the Plenio Player finds the song by that too). A user template that could not be read was listed with the error's text, which for a file is its absolute path - now with the kind of error only. Plenio's error answers to a request from another computer keep a path's last two parts. A party song's record path no longer reaches the guests' page.

</details>

<details><summary><b>Fixed</b> (2)</summary>

- **A brief's list field keeps your choice.** After a few templates had been tried, choosing a value in a field such as *language* could jump back to empty: the brief remembered every value a template had ever shown in a field and took your choice for an old template's value, which the next template then replaced. A value you choose is now yours and stays, whichever templates come after it; the values the frontend puts back by itself after a *vocals* change are still told apart.
- **Share as a player works on a phone.** On a phone the dialog's two columns did not fit: the list of songs could not be seen or ticked properly, and the dialog did not scroll, upright or on its side. On a small or low screen it now fills the screen in one column that scrolls - the songs to tick first, then the choices, the button always at hand.

</details>
